# AGENTS.md — rules for AI coding agents working on this repo

This is a solo-maintained Madrasah ERP (React/Vite client + Express/Postgres
server). There is no CI and no second reviewer — this file, plus
`npm run check`, is the only safety net. Read this before making any change.

## Non-negotiable rules

1. **One task at a time, minimal diff.** Touch only the files needed for the
   current task. Do not refactor, rename, or "clean up" unrelated code in the
   same change, even if you notice something else that looks wrong — mention
   it instead of fixing it.
2. **A task is not finished until `npm run check` passes.** Run it after
   every change. If it fails, fix the failure before reporting the task done.
   Do not report a task as complete based on the code "looking right."
3. **Never hand-edit a generated file.** `client/src/lib/roles.generated.ts`
   is generated by `scripts/sync-roles.js` from `server/src/config/roles.js`.
   If a role or permission needs to change, edit `server/src/config/roles.js`
   only — `npm run check` regenerates the client copy automatically.
4. **Protected paths — stop and ask before editing, don't just proceed:**
   - `server/src/middleware/auth.js` and anything else handling
     login/JWT/password hashing
   - `server/src/middleware/rbac.js` and `server/src/config/roles.js`
     (who can access what)
   - `server/src/routes/backup.js` and anything touching Google Drive backup
     or restore
   - Any SQL migration / schema file under `server/sql/`
   - `server/src/index.js` security config (helmet/CSP block, rate limiters)
   A change to these is allowed when the task is explicitly about one of
   them — but explain what changed and why before considering it done.
5. **No new dependencies without saying so first.** Don't add an npm package
   to solve something that can be done with what's already installed, and
   if one is genuinely needed, name it and why before installing.

## Workflow

1. Restate the task in one line before starting, so scope is explicit.
2. Make the change.
3. Run `npm run check` (see below for what it does).
4. If it fails: read the error, fix only what it points at, re-run. Repeat
   until it passes.
5. Report what changed, and explicitly confirm `npm run check` passed.

## What `npm run check` does

```
npm run sync:roles   → regenerates client/src/lib/roles.generated.ts
npm run lint          → eslint on the client
npm run typecheck     → tsc -b --noEmit on the client
npm run build          → tsc -b --noEmit && vite build (client)
npm run test:server   → syntax-checks every server/src/**/*.js file
```

This is a syntax/type/build gate, not a full test suite — it will not catch
every logic bug. Treat a pass as "didn't obviously break anything," not as
"definitely correct." (See docs/DEVELOPER_GUIDE for how to manually smoke-test
login, student create, attendance, and backup after anything touching those
areas.)

`npm run check` does NOT run `npm run test:backup` (it needs a separate
throwaway test database — see BACKUP_TEST_DATABASE_URL in .env.example).
Run it manually after touching anything in server/src/routes/backup.js,
restoreLock.js, or backupEncryption.js: it seeds data, backs it up, mutates
the data, restores, and checks the database matches the pre-mutation state
exactly, plus a few rejection/concurrency cases.

## Single source of truth

- Roles & permissions: `server/src/config/roles.js` (client copy is generated
  — see rule 3 above).
- Everything else currently has no single-source enforcement; if you notice
  another value duplicated between client and server, flag it instead of
  silently fixing it in only one place.
