# ডেটা রিডানডেন্সি ও ফেইলওভার সিস্টেম

## এটা কী করে

এই প্রজেক্ট এখন **দুটো সম্পূর্ণ আলাদা Postgres ডাটাবেজে** (দুটো আলাদা Neon অ্যাকাউন্ট) ডেটা রাখে:

- **Primary** (`DATABASE_URL`) — স্বাভাবিক অবস্থায় সব read/write এখানেই হয়।
- **Backup** (`DATABASE_URL_BACKUP`) — প্রতিটা write স্বয়ংক্রিয়ভাবে এখানেও mirror হয়।

Primary ডাটাবেজে সংযোগ ব্যর্থ হলে (ডাউন, নেটওয়ার্ক সমস্যা ইত্যাদি), সাইট **স্বয়ংক্রিয়ভাবে backup ডাটাবেজে সুইচ করে** এবং চালু থাকে। Primary আবার ফিরে এলে **স্বয়ংক্রিয়ভাবে ফিরে যায় না** — এটা ইচ্ছাকৃত (নিচে কারণ ব্যাখ্যা করা আছে)।

## কেন automatic switch-back নেই

Failover-এর সময় থেকে backup ডাটাবেজে যে নতুন ডেটা লেখা হয়েছে (নতুন ছাত্র ভর্তি, ফি জমা ইত্যাদি), সেগুলো primary-তে নেই। Primary সুস্থ হওয়া মাত্র যদি সিস্টেম নিজে থেকে আবার primary-কে ব্যবহার শুরু করে, তাহলে failover চলাকালীন backup-এ যোগ হওয়া সব ডেটা **হারিয়ে যাবে** (কারণ সাইট আবার পুরনো primary ডেটা দেখাতে শুরু করবে)।

তাই switch-back সবসময় **ম্যানুয়াল**:

1. Primary সুস্থ হয়েছে নিশ্চিত করুন (Neon ড্যাশবোর্ড দেখুন)।
2. `npm run backup-db:sync-back` চালান (server ফোল্ডার থেকে) — এটা backup-এর সব ডেটা primary-তে কপি করে দেবে (primary-র পুরনো ডেটা মুছে backup দিয়ে replace হবে)।
3. স্ক্রিপ্ট শেষ হলে সার্ভার রিস্টার্ট করুন — সার্ভার সবসময় বুট হওয়ার সময় primary দিয়েই শুরু করে।

## প্রথমবার সেটআপ

1. দ্বিতীয় Neon প্রজেক্ট/অ্যাকাউন্ট তৈরি করুন, connection string কপি করুন।
2. `.env`-এ `DATABASE_URL_BACKUP=...` যোগ করুন।
3. (ঐচ্ছিক কিন্তু সুপারিশকৃত) `PLATFORM_OWNER_EMAIL=...` যোগ করুন — failover হলে এই ইমেইলে সতর্কতা যাবে (`RESEND_API_KEY` আগে থেকেই সেট থাকতে হবে)।
4. `npm run backup-db:copy` চালান (server ফোল্ডার থেকে) — এটা বর্তমান সব ডেটা (registry + সব tenant schema) একবারে backup ডাটাবেজে কপি করে দেবে।
5. সার্ভার রিস্টার্ট/ডিপ্লয় করুন — dual-write ও auto-failover এখন সক্রিয়।

## কী কী স্বয়ংক্রিয়

- প্রতিটা write (INSERT/UPDATE/DELETE) primary-তে হওয়ার পর backup-এও পাঠানো হয় (asynchronous — এটা ইউজারের রিকোয়েস্ট ধীর করে না)।
- Backup write ব্যর্থ হলে শুধু log হয়; বারবার (৩ বারের বেশি টানা) ব্যর্থ হলে ইমেইল অ্যালার্ট যায়।
- Primary সংযোগ ব্যর্থ হলে (connection-level error — timeout, refused, ইত্যাদি) সিস্টেম backup-এ সুইচ করে এবং ইমেইল অ্যালার্ট পাঠায়।

## কী কী ম্যানুয়াল

- Primary সুস্থ হওয়ার পর ফিরে আসা (`npm run backup-db:sync-back` + রিস্টার্ট)।
- দ্বিতীয় Neon অ্যাকাউন্ট/প্রজেক্ট তৈরি করা (এটা কোড দিয়ে করা যায় না)।

## সীমাবদ্ধতা যা জানা দরকার

- Primary ও backup ডাটাবেজ কখনো ১০০% এক মুহূর্তে সমান থাকে না (mirror asynchronous) — তাই সংযোগ বিচ্ছিন্ন হওয়ার ঠিক মুহূর্তে যে write চলছিল, তা backup-এ নাও থাকতে পারে।
- Failover চলাকালীন যদি primary **এবং** backup দুটোই ডাউন হয়, সাইট সম্পূর্ণ বন্ধ হয়ে যাবে (এই কনফিগারেশনে এর বেশি redundancy নেই)।
- Failover অবস্থায় থাকার সময় backup ডাটাবেজেরও কোনো নিজস্ব ব্যাকআপ (দ্বিতীয় স্তর) নেই — যত দ্রুত সম্ভব sync-back করে normal অবস্থায় ফেরা উচিত।
