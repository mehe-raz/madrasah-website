# পরিকল্পনা: রিপোর্ট সেকশনে "কল লিস্ট" ভিউ (ছাত্র তালিকা + বকেয়া তালিকা)

তৈরি: 2026-08-10 · প্রজেক্ট: madrasah-website · স্ট্যাটাস: **শুধু পরিকল্পনা — এখনো কোনো কোড লেখা হয়নি**

---

## ১. এখন কী চাইছেন (সংক্ষেপে)

`Reports.tsx`-এর **"ছাত্র তালিকা"** ও **"বকেয়া তালিকা"** — এই দুই কার্ডে ক্লিক করলে এখন
সরাসরি প্রিন্ট/CSV হয়ে যায়। আপনি চান:

1. কার্ডে ক্লিক করলে আগে একটা **ফুল-পেজ লিস্ট ভিউ** খুলবে (ইন-অ্যাপ পেজ, আলাদা ব্রাউজার
   ট্যাবের দরকার নেই) — সেখানে **Back/Exit বাটন** দিয়ে ফেরত আসা যাবে।
2. প্রতিটা ছাত্রের সারিতে একটা **সবুজ কল বাটন** (ফোন-ডায়াল আইকন) থাকবে — মোবাইল থেকে
   ক্লিক করলে সরাসরি ফোনের ডায়ালারে ঐ নম্বরটা নিয়ে যাবে।
3. এই মাসে কাকে কল দেওয়া হয়েছে আর কাকে দেওয়া হয়নি — সেটা **সেভ/মার্ক** থাকবে:
   - কল দেওয়া হয়েছে → সবুজ চেক-মার্ক
   - এখনো কল দেওয়া হয়নি → লাল চিহ্ন
4. একই পেজের ভেতরেই **প্রিন্ট ও CSV ডাউনলোড** বাটন থাকবে (এখন যেটা কার্ডে ক্লিক করলেই
   হয়ে যায়, সেটা এখন এই নতুন পেজে সরে যাবে)।

## ২. প্রজেক্টে এখন যা আছে (আমি জিপ খুলে যাচাই করেছি)

| জিনিস | ফাইল | অবস্থা |
|---|---|---|
| রিপোর্ট কার্ড গ্রিড (ছাত্র তালিকা/বকেয়া/হাজিরা/আয়/ব্যয়/হিফজ) | `client/src/modules/Reports.tsx` | আছে |
| প্রিন্ট + CSV এক্সপোর্ট লজিক (সব রিপোর্ট কাইন্ডের জন্য) | `client/src/lib/exportReports.ts` | আছে, কাজ করছে |
| প্রিন্ট উইন্ডো রেন্ডারার | `client/src/lib/printReport.ts` | আছে |
| ছাত্র লিস্ট আনা (`api.getStudents()`), phone ফিল্ড | `client/src/lib/api.ts`, `types/index.ts` | আছে — `Student.phone` আগে থেকেই আছে |
| রিপোর্ট পারমিশন ম্যাপ (students/due → `"students"` পারমিশন) | `Reports.tsx` এর `REPORT_PERMISSION` | আছে, রিইউজ করা যাবে |
| আইকন সেট (lucide-react) | `client/src/lib/icons.ts` | আছে, কিন্তু **ফোন/কল আইকন এখনো যোগ করা হয়নি** |
| `tel:` লিংক / কল বাটন | — | **নেই, নতুন বানাতে হবে** |
| কে কাকে কল দিয়েছে তার রেকর্ড (DB) | — | **নেই — নতুন টেবিল লাগবে** |
| ফুল-পেজ ইন-অ্যাপ লিস্ট ভিউ (আলাদা রুট) | — | **নেই — এখন কার্ড ক্লিক = সরাসরি প্রিন্ট/CSV, কোনো intermediate পেজ নেই** |

**সংক্ষেপে:** প্রিন্ট/ডাউনলোড লজিক পুরোটাই রেডি এবং reuse হবে (নতুন করে লিখতে হবে না)।
নতুন যা লাগবে তা তিনটা জিনিস — (ক) একটা নতুন ইন-অ্যাপ পেজ, (খ) কল বাটন, (গ) "এই মাসে
কল দেওয়া হয়েছে কিনা" এই তথ্যটা **সেভ রাখার জন্য একটা নতুন DB টেবিল + API**।

> **কেন শুধু ব্রাউজারে (localStorage) মার্ক না রেখে DB-তে রাখা দরকার:** মাদ্রাসায় একাধিক
> স্টাফ/অ্যাডমিন আলাদা আলাদা ডিভাইস/ব্রাউজার থেকে লগইন করে কল দিতে পারেন। শুধু একজনের
> ব্রাউজারে মার্ক থাকলে অন্য কেউ দেখবে না কে কাকে কল দিয়েছে, ফলে ডুপ্লিকেট কল হবে বা কেউ
> বাদ পড়ে যাবে — যেটা এই ফিচারের মূল উদ্দেশ্যকে নষ্ট করে। তাই এটা সার্ভারে সেভ হবে।

## ৩. যে অ্যাসাম্পশনগুলো নিয়ে এগোচ্ছি (ভুল হলে পড়ার পর জানাবেন)

- কল বাটন `Student.phone` ফিল্ডের নম্বরে কল করবে (এটাই এখন প্রিন্ট/CSV-এ "Phone" কলাম
  হিসেবে দেখানো হয়, তাই এটাই primary contact ধরে নিচ্ছি)। `fatherMobile`/`motherMobile`/
  `guardianMobile` আলাদা যোগ করা এখন স্কোপে রাখছি না — চাইলে Phase ২-এর পর যোগ করা যাবে।
- "এই মাসে কল দেওয়া হয়েছে" — মাস মানে ক্যালেন্ডার মাস (যেমন 2026-08)। নতুন মাস শুরু হলে
  সব ছাত্রের মার্ক স্বয়ংক্রিয়ভাবে আবার "লাল/কল দেওয়া হয়নি" হয়ে যাবে (পুরনো মাসের রেকর্ড
  মুছে যাবে না, শুধু নতুন মাসের জন্য আলাদা সারি হবে)।
- এই ফিচার শুধু **"ছাত্র তালিকা"** ও **"বকেয়া তালিকা"** — এই দুই রিপোর্ট কার্ডের জন্য। বাকি
  চারটা (হাজিরা/আয়/ব্যয়/হিফজ) আগের মতোই সরাসরি প্রিন্ট/CSV থাকবে — ওখানে ফোন-কল করার
  কোনো অর্থ নেই।
- পারমিশন: নতুন কোনো permission বানাচ্ছি না — এখন যেটা আছে (`students` permission,
  `REPORT_PERMISSION` ম্যাপে students+due দুটোই এটার সাথে বাঁধা) সেটাই রিইউজ হবে।
- চেকমার্ক শুধু "কল দেওয়া হয়েছে/হয়নি" বোঝাবে — কল রিসিভ হয়েছে/কথা হয়েছে কিনা সেটা ট্র্যাক
  করছি না (সেটা চাইলে future ফিচার)।

## ৪. কাজ কয় ভাগে হবে — **৩ ভাগে** (Phase 1 → 2 → 3)

আপনি বলেছেন ২ নাকি ৩ ভাগ আমি ঠিক করি — এখানে ৩ ভাগে ভাগ করছি কারণ কাজটার দুটো আলাদা
স্তর আছে (ডেটাবেজ+API আলাদা স্তর, UI আলাদা স্তর) এবং শেষে মোবাইলে আসল ডিভাইসে টেস্ট করে
ছোটখাটো এজ-কেস ঠিক করার জন্য আলাদা ধাপ রাখা ভালো। প্রতিটা ধাপের পরে `npm run check` +
আপনার প্যাকেজড CMD দিয়ে যাচাই হবে, ধাপ পাস না করলে পরের ধাপে যাব না।

### Phase 1 — ব্যাকএন্ড: DB টেবিল + API (নতুন কোড, নতুন ফাইল)

- `server/sql/supabase_schema.sql`-এ নতুন টেবিল যোগ:
  ```sql
  create table if not exists student_call_log (
    id integer generated by default as identity primary key,
    "studentId" integer not null references students(id) on delete cascade,
    "callMonth" text not null,               -- 'YYYY-MM'
    "calledBy" integer references users(id),
    "calledAt" timestamptz not null default now(),
    unique ("studentId", "callMonth")
  );
  ```
  (প্রজেক্টের বিদ্যমান কনভেনশন অনুযায়ী — `attendance` টেবিলের প্যাটার্ন অনুসরণ করে)
- `server/src/routes/students.js`-এ (অথবা প্রয়োজনে ছোট নতুন ফাইল) দুইটা নতুন এন্ডপয়েন্ট:
  - `GET /api/students/call-log?month=YYYY-MM` — ঐ মাসে কোন কোন `studentId` কল
    হয়েছে তার লিস্ট রিটার্ন করবে (existing `requirePermission("students")` এর ভেতরেই)।
  - `POST /api/students/:id/call-log` (body: `{ month }`) — মার্ক করবে (upsert, ইতিমধ্যে
    মার্ক থাকলে no-op)।
  - `DELETE /api/students/:id/call-log?month=YYYY-MM` — ভুল করে মার্ক হয়ে গেলে
    আনমার্ক করার জন্য।
- এগুলো existing `students` পারমিশনের নিচেই থাকবে, নতুন permission লাগবে না।
- **টেস্ট:** `npm run check` (server syntax check) + ম্যানুয়ালি একটা কল সেভ করে দেখা।

### Phase 2 — ফ্রন্টএন্ড: নতুন "কল লিস্ট" পেজ + Reports.tsx-এ ওয়্যারিং

- নতুন কম্পোনেন্ট: `client/src/modules/reports/CallListView.tsx` (নতুন ফোল্ডার/ফাইল)
  - React Router-এ নতুন রুট, যেমন `/reports/call-list/:kind` (`kind` = `students` | `due`)।
  - পেজের ভেতরে: টাইটেল, Back/Exit বাটন (আগের Reports পেজে ফিরিয়ে দেবে), সারি-ভিত্তিক
    টেবিল (Roll, Name, Class, Phone, Due — kind অনুযায়ী কলাম কিছুটা আলাদা, এক্সিস্টিং
    `studentListRows`/`dueListRows`-এর কলাম মিলিয়ে), প্রতি সারিতে:
    - সবুজ কল বাটন — `<a href="tel:...">` (নতুন Phone আইকন, `icons.ts`-এ যোগ হবে)।
      ফোন নম্বর না থাকলে বাটন ডিসেবল + "নম্বর নেই" টুলটিপ।
    - কল-স্ট্যাটাস মার্ক (চেকবক্স/ব্যাজ) — Phase ১-এর API থেকে লোড হওয়া ডেটা অনুযায়ী
      সবুজ/লাল। কল বাটনে ক্লিক করলে auto-mark (POST) হবে; চেকবক্সে ম্যানুয়ালি ক্লিক
      করেও টগল করা যাবে (POST/DELETE)।
  - পেজের উপরে/নিচে **প্রিন্ট** ও **CSV ডাউনলোড** বাটন — এক্সিস্টিং
    `printReportTable()` / CSV এক্সপোর্ট ফাংশন রিইউজ (নতুন করে লিখতে হবে না, শুধু কল
    করা হবে)।
  - উপরে একটা ছোট সামারি: "মোট X জন · কল হয়েছে Y জন · বাকি Z জন"।
- `Reports.tsx`: "ছাত্র তালিকা" ও "বকেয়া তালিকা" কার্ডের ক্লিক-বিহেভিয়ার বদলে navigate
  করবে `/reports/call-list/students` বা `/reports/call-list/due`-তে (আগের মতো সরাসরি
  `handleExport` কল হবে না এই দুই কার্ডের জন্য — বাকি ৪টা কার্ড অপরিবর্তিত থাকবে)।
- **টেস্ট:** `npm run check` (lint+typecheck+build) + ম্যানুয়াল স্মোক-টেস্ট (ডেস্কটপ
  ব্রাউজারে পেজ খোলা, প্রিন্ট/CSV কাজ করা, চেকবক্স টগল হওয়া)।

### Phase 3 — পলিশ, এজ-কেস, মোবাইল টেস্ট, ডক আপডেট

- মোবাইল রেসপন্সিভনেস চেক (`tel:` লিংক আসলে মোবাইল ডিভাইসেই সবচেয়ে গুরুত্বপূর্ণ — এমুলেটর
  নয়, আপনার আসল ফোনে টেস্ট করে দেখাটা জরুরি)।
- এজ-কেস: ফোন নম্বর খালি/ভুল ফরম্যাট, একই ছাত্র দুইবার মার্ক করার race condition (unique
  constraint দিয়ে হ্যান্ডল), অনেক ছাত্র (৩০০+) থাকলে পেজ পারফরম্যান্স।
  Accessibility: কল বাটন/চেকবক্সে `aria-label`।
- `docs/PROJECT_MAP.md`-এ এক লাইন নোট যোগ (নতুন রুট/টেবিলের কথা, যাতে ভবিষ্যতে অন্য
  এজেন্ট সহজে খুঁজে পায়)।
- **টেস্ট:** `npm run check` + আপনার ফোনে বাস্তব কল-বাটন টেস্ট।

## ৫. AGENTS.md / CURRENT_TASK.md সম্পর্কিত নোট

`docs/CURRENT_TASK.md`-এ এখন একটা **অসম্পূর্ণ, ভিন্ন কাজ** পড়ে আছে (exam-type/result

নয়, তাই:
- আমি এই কাজটাকে সেই কাজের Part হিসেবে না লিখে **আলাদা এন্ট্রি** হিসেবে
  `CURRENT_TASK.md`-এ যোগ করব (AGENTS.md-এর phase-naming rule অনুযায়ী), পুরনো
  exam-type এন্ট্রিটা যেমন আছে তেমনই রেখে দেব — মুছব না।
- আপনি চাইলে আগে সেই বাকি কাজ (exam-type Part 4) শেষ করাতে পারেন, অথবা এই নতুন কাজ
  আগে করতে বলতে পারেন — দুটো আলাদা ফাইল/এলাকায় কাজ করছে বলে একসাথেও এগোনো সম্ভব।

## ৬. পরবর্তী ধাপ

এই পরিকল্পনা পড়ে ঠিক থাকলে **"শুরু কর"** লিখুন — আমি **Phase 1** দিয়ে শুরু করব, একবারে
এক ধাপ। প্রতিটা ধাপ শেষে আপনার preference অনুযায়ী শুধু পরিবর্তিত/নতুন ফাইলের zip +
এক্সট্র্যাক্ট→npm install→npm run check→(পাস করলে) commit/push — এই একটামাত্র CMD
কমান্ড দেব।

কোথাও অ্যাসাম্পশন (সেকশন ৩) ভুল মনে হলে, শুরু করার আগে বলে দিলে সেভাবে প্ল্যান
এডজাস্ট করে নেব।
