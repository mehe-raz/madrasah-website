## ১. এখন কী চাইছেন (সংক্ষেপে)

এই প্রতিষ্ঠান (ইউজারের নিজস্ব SaaS কোম্পানি) এখন এই কোডবেস দিয়ে শুধু মাদ্রাসাকে
সার্ভিস দেয়। ইউজার চান একই কোডবেস দিয়ে দ্বিতীয় একটা মোড/ভ্যারিয়েন্ট — যেখানে
স্কুল, কলেজ, বা কোচিং সেন্টার সাইনআপ করলে তারা এমন একটা প্রোডাক্ট পাবে যেখানে
কোনো মাদ্রাসা/আরবি-নির্দিষ্ট শব্দ বা ফিচার থাকবে না, কিন্তু হিসাব-নিকাশ, ছাত্র
ভর্তি, অ্যাটেন্ডেন্স, রেজাল্ট ইত্যাদি কোর ফিচার আগের মতোই কাজ করবে।

**প্রেক্ষাপট আবিষ্কার (আগের গবেষণা সেশনে সম্পূর্ণ কোডবেস লাইন বাই লাইন দেখা
হয়েছে):**

## ২. প্রজেক্টে এখন যা আছে (আবিষ্কার)

### ২.১ ভালো খবর — এগুলো ইতিমধ্যেই জেনারিক, পরিবর্তন লাগবে না
- **ক্লাস/জামাত স্ট্রাকচার** (`server/src/lib/classTree.js`) — কোড হার্ডকোড
  না, DB-র `settings` টেবিলে JSON ব্লব হিসেবে থাকা একটা সম্পূর্ণ এডিটেবল
  ট্রি (বিভাগ → গ্রুপ/নেসাব → জামাত/ক্লাস)। মাদ্রাসার "হিফজ বিভাগ" ইত্যাদি
  শুধু `DEFAULT_CLASS_TREE`-এর **ডিফল্ট সিড ডেটা** (লাইন ১৫২–২৩৯), স্ট্রাকচার
  নিজেই জেনারিক।
- **রোল সিস্টেম** (`server/src/config/roles.js`) — `Admin, Accountant,
  Teacher, Hostel Manager` সব ইংরেজি, জেনারিক নাম। মাদ্রাসা-নির্দিষ্ট কোনো
  রোল নাম কোডে হার্ডকোড নেই।
- **সাবজেক্ট লিস্ট, exam types, attendance, income/expenses, SMS, payment
  gateway, camera, staff** — এই মডিউলগুলোতে কোথাও মাদ্রাসা/ইসলামিক-নির্দিষ্ট
  লজিক পাওয়া যায়নি।
- **পাবলিক মার্কেটিং পেজ** (`About.tsx`, `Pricing.tsx`, `Admission.tsx`) —
  কনটেন্ট সাইট-এডিটর দিয়ে অ্যাডমিন-এডিটেবল, কোড-হার্ডকোড মাদ্রাসা শব্দ নেই।

### ২.২ যেখানে আসল কাজ — ৪টা জায়গায় কেন্দ্রীভূত

1. **"হিফজ ট্র্যাকিং" — সম্পূর্ণ আলাদা একটা ফিচার-মডিউল**, নিচের প্রতিটা
   স্তরে জড়িয়ে আছে:
   - Route: `server/src/routes/hifz.js` — `WHERE dept = 'Hifz'` হার্ডকোড
   - Permission key: `server/src/config/roles.js` — `"hifz"`, Admin ও
     Teacher রোলে দেওয়া
   - Route mapping: `ROUTE_PERMISSION["/api/hifz"] = "hifz"`
   - Plan gating: `server/src/config/planFeatures.js` — `hifzTracking`
     ফ্ল্যাগ, **শুধু প্ল্যান-ভিত্তিক**, প্রতিষ্ঠান-টাইপ-ভিত্তিক না
   - Sidebar: `client/src/components/Sidebar.tsx` —
     `{ id: "hifz", feature: "hifzTracking" }`
   - Page: `client/src/modules/HifzTracking.tsx`
   - Reports/Settings মডিউলেও হিফজ-সম্পর্কিত সেকশন আছে

2. **`student.dept` এনাম** — `client/src/lib/labels.ts`-এ হার্ডকোড
   `DEPT_OPTIONS = ["Hifz", "Nazera", "Kitab", "Nurani", "General"]`।

3. **`para` (পারা) কলাম** — `students` টেবিলের কোর কলাম (ঐচ্ছিক না),
   `server/src/models/studentAdmission.js`-এ `NUMBER_FIELDS`-এ, ভ্যালিডেশন
   `Math.min(30, ...)`। সব ছাত্রের প্রিন্ট রিপোর্টে দেখায়
   (`server/src/routes/students.js:540`), যদিও শুধু হিফজ ছাত্রদের জন্য
   প্রাসঙ্গিক।

4. **প্রতিষ্ঠানের "টাইপ" বলে কিছু নেই** — `registry.institutions` টেবিলে
   madrasah vs school vs coaching আলাদা করার কোনো কলাম নেই। **এটাই মূল
   ফাউন্ডেশন গ্যাপ** — বাকি সব সমাধান এর উপর নির্ভর করে।

### ২.৩ i18n টেক্সট লেয়ার — খুব ছোট কাজ
`client/src/i18n/bn.ts` ও `en.ts`-এ "মাদরাসা/madrasa" শব্দ পাওয়া গেছে মোট
মাত্র এই কয়টা key-তে: `madrasaInfo` (দুই জায়গায় ডুপ্লিকেট), `name:
"মাদ্রাসার নাম"`, Pricing subtitle, `restoreHelp`, `departmentsSummary`, এবং
`client/src/pages/Home.tsx:24`-এর ফলব্যাক `"মাদ্রাসা"`।

## ৩. Phase ব্রেকডাউন

### Phase 1 — DB: `institution_type` কলাম
- `server/sql/registry_schema.sql`-এ `registry.institutions` টেবিলে
  `institution_type` কলাম যোগ (`alter table ... add column if not exists`),
  ডিফল্ট `'madrasah'` (বিদ্যমান টেন্যান্ট backward-compatible)।
- অনুমোদিত ভ্যালু নিয়ে **খোলা প্রশ্ন ১** (নিচে §৫) — কনফার্ম করা লাগবে।

### Phase 2 — সাইনআপ ফ্লো + classTree ডিফল্ট সিড
- `server/src/routes/publicSignup.js` + ফ্রন্টএন্ড সাইনআপ ফর্মে "প্রতিষ্ঠানের
  ধরন" সিলেক্টর যোগ।
- নতুন টেন্যান্ট তৈরির সময় টাইপ অনুযায়ী ভিন্ন classTree ডিফল্ট সিড ব্যবহার
  (`classTree.js`-এ `DEFAULT_CLASS_TREE`-এর পাশে একটা `DEFAULT_CLASS_TREE_GENERAL`
  যোগ, madrasah না হলে সেটা ব্যবহার হবে)।

### Phase 3 — হিফজ ফিচার গেটিং: প্ল্যান + টাইপ দুটোই চেক
- `planFeatures.js`-এর গেট লজিকে `institution_type !== 'madrasah'` হলে
  `hifzTracking` জোরপূর্বক `false` (প্ল্যান যাই হোক)।
- Route middleware (hifz.js-এ ঢোকার আগে) ও Sidebar — দুই জায়গাতেই এই এক্সট্রা
  চেক প্রতিফলিত হতে হবে যাতে সরাসরি API কল করেও general-টাইপ টেন্যান্ট হিফজ
  ডেটা দেখতে না পারে।

### Phase 4 — `dept` এনাম জেনারালাইজ
- general-টাইপ প্রতিষ্ঠানে অ্যাডমিশন ফর্মে `dept` ফিল্ড হাইড অথবা
  classTree-র টপ-লেভেল বিভাগ থেকে অটো-ডিরাইভ (বর্তমান
  `TREE_TOP_LEVEL_TO_DEPT` ম্যাপিং প্যাটার্নেই general বিভাগগুলোর জন্যও
  ম্যাপিং যোগ)।

### Phase 5 — `para` কলাম কন্ডিশনাল
- প্রিন্ট রিপোর্ট (`routes/students.js`, `client/src/lib/printReport.ts`),
  অ্যাডমিশন ফর্ম, স্টুডেন্ট প্রোফাইল — `hifzTracking` ফিচার অন থাকলে তবেই
  "পারা" দেখানো (Phase 3-এর ফ্ল্যাগের সাথেই বাঁধা, আলাদা নতুন কন্ডিশন লাগবে
  না)।

### Phase 6 — i18n টেক্সট ক্লিনআপ
- §২.৩-এ তালিকাভুক্ত ~৯টা key জেনেরিক টেক্সটে বদলানো ("প্রতিষ্ঠানের

### Phase 7 — মার্কেটিং/হোমপেজ ফলব্যাক টেক্সট
