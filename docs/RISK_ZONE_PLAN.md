# পরিকল্পনা: "রিস্ক জোন" — ২+ মাস বেতন বকেয়া থাকা ছাত্রদের আলাদা লিস্ট

তৈরি: 2026-08-10 · প্রজেক্ট: madrasah-website · স্ট্যাটাস: **শুধু পরিকল্পনা — এখনো কোনো কোড লেখা হয়নি**

---

## ১. এখন কী চাইছেন (সংক্ষেপে)

যেসব ছাত্র **টানা দুই মাসের বেশি বেতন দেয়নি**, তাদেরকে অ্যাডমিন/মালিক যাতে
ড্যাশবোর্ডের অন্য সব তথ্যের পাশাপাশি **একটা আলাদা জায়গা থেকে সহজে দেখতে
পারে** — একটা "রিস্ক জোন" লিস্ট, যেখান থেকে সরাসরি তাদের কল করাও যাবে।

## ২. প্রজেক্টে এখন যা আছে (জিপ খুলে যাচাই করেছি)

| জিনিস | ফাইল | অবস্থা |
|---|---|---|
| প্রতি ছাত্রের মাসিক বেতন (`fee`) ও সঞ্চিত বকেয়া (`due`) কলাম | `server/sql/supabase_schema.sql` (`students` টেবিল) | আছে |
| "কত মাস বকেয়া" — আলাদা কোনো কলাম/হিসাব | — | **নেই** — শুধু সঞ্চিত টাকার অঙ্ক (`due`) আছে, মাস-সংখ্যা হিসেব করে রাখা হয় না |
| ড্যাশবোর্ডে বকেয়া-সংক্রান্ত স্ট্যাট কার্ড (মোট বকেয়া, বকেয়া ছাত্র সংখ্যা) | `server/src/routes/dashboard.js`, `client/src/modules/Dashboard.tsx` | আছে — কিন্তু "কতজন ২+ মাস বকেয়া" আলাদা করে নেই, ক্লিক করলে লিস্টে যাওয়ার লিংকও নেই |
| বকেয়া ছাত্রদের পেজিনেটেড লিস্ট (`dueOnly` ফিল্টার) | `server/src/routes/students.js` (`GET /api/students`) | আছে — `due > 0` ফিল্টার করে, রিইউজ করা যাবে |
| ফুল-পেজ "কল লিস্ট" ভিউ (রোল/নাম/ক্লাস/বকেয়া + সবুজ কল বাটন + প্রিন্ট/CSV + "কল দেওয়া হয়েছে" মার্ক) | `client/src/modules/reports/CallListView.tsx` (`docs/CALL_LIST_PLAN.md` অনুযায়ী তৈরি, ইতিমধ্যে **সম্পন্ন**) | আছে — এখন `kind` = `students` বা `due`, `ReportKind` টাইপ ৩ জায়গায় (`exportReports.ts`, `Reports.tsx`, `CallListView.tsx`) |
| প্রিন্ট/CSV এক্সপোর্ট লজিক | `client/src/lib/exportReports.ts` | আছে, `ReportKind` অনুযায়ী কাজ করে |

**সংক্ষেপে:** কল-বাটন, কল-মার্কিং, প্রিন্ট/CSV, পেজিনেটেড বকেয়া-লিস্ট — এই
সব বিল্ডিং ব্লক ইতিমধ্যে তৈরি আছে (কল লিস্ট ফিচার থেকে)। নতুন যা লাগবে
মূলত: (ক) **"২+ মাস বকেয়া" এর হিসাব** (নতুন লজিক, কারণ এটা এখন কোথাও
গণনা হয় না), (খ) ড্যাশবোর্ডে একটা নতুন স্ট্যাট কার্ড + তা থেকে লিস্টে যাওয়ার
লিংক, (গ) কল-লিস্ট ভিউকে এই নতুন ফিল্টারের জন্য এক্সটেন্ড করা।

## ৩. মূল অ্যাসাম্পশন — এটা শুরু করার আগে আপনার কনফার্মেশন দরকার

এই প্রজেক্টে প্রতি মাসের বেতন আলাদা করে রেকর্ড হয় না (যেমন "জানুয়ারি
পরিশোধ", "ফেব্রুয়ারি পরিশোধ" — এমন কোনো টেবিল নেই)। যা আছে তা হলো একটা
সঞ্চিত টাকার অঙ্ক (`due`)। তাই "২ মাসের বেশি বকেয়া" বের করার একমাত্র
বাস্তবসম্মত উপায় —

```
মাস-সংখ্যা (আনুমানিক) = due ÷ fee   (ভাগফলের পূর্ণ অংশ)
```

যেমন কোনো ছাত্রের মাসিক বেতন ১৫০০ টাকা আর সঞ্চিত বকেয়া ৩২০০ টাকা হলে, ধরে
নেওয়া হবে সে ২ মাসের বেশি বকেয়া (৩২০০ ÷ ১৫০০ ≈ ২.১)।

**এটা একটা আনুমানিক (approximate) হিসাব, নিখুঁত না** — কারণ আংশিক
পেমেন্ট, বেতন মাঝপথে বাড়া/কমা, বা ভর্তির মাস হিসেবে না ধরাসহ নানা কারণে
আসল মাস-সংখ্যার সাথে সামান্য গরমিল হতে পারে। এই সীমাবদ্ধতা মেনে নিয়েই
এগোনো ঠিক আছে কিনা — অথবা ভবিষ্যতে প্রতি-মাস আলাদা রেকর্ড রাখার (বড়,
আলাদা কাজ) দরকার আছে কিনা — এটা আপনার সিদ্ধান্ত।

অন্য যেসব অ্যাসাম্পশন নিয়ে এগোচ্ছি (ভুল হলে "শুরু কর" বলার আগে জানাবেন):

- **থ্রেশহোল্ড: "২ মাসের বেশি" মানে ২ মাস বা তার বেশি বকেয়া (মাস-সংখ্যা ≥ ২)** ধরছি,
  ঠিক ৩ মাস পার হওয়া লাগবে না। ভুল হলে জানাবেন, সংখ্যাটা এক লাইনে বদলে
  দেওয়া সহজ।
- ইনঅ্যাক্টিভ/ছুটিতে থাকা (`status ≠ "সক্রিয়"`) ছাত্রদের এই লিস্টে দেখানো হবে
  না — শুধু বর্তমানে সক্রিয় ছাত্র। "বকেয়া তালিকা" রিপোর্ট কার্ডও একই নিয়ম
  মানে ধরেই এগোচ্ছি।
- `fee` = 0 (বিরল, কিন্তু possible যদি কোনো ছাত্রের বেতন মওকুফ থাকে) হলে সেই
  ছাত্রকে হিসাবের বাইরে রাখা হবে (division-by-zero এড়াতে), রিস্ক-জোনে
  দেখানো হবে না।
- কল-বাটন/কল-মার্কিং একই লজিক রিইউজ হবে যা "কল লিস্ট" ফিচারে আছে — নতুন
  কোনো টেবিল/এন্ডপয়েন্ট লাগবে না এই অংশের জন্য।
- পারমিশন: নতুন কোনো permission বানাচ্ছি না — এখন যা আছে (dashboard +
  students permission) সেটাই রিইউজ হবে।

## ৪. কাজ কয় ভাগে হবে — **৩ ভাগে** (Phase 1 → 2 → 3)

কেন ৩ ভাগ: (ক) আগে হিসাবের সংজ্ঞাটা (মাস-সংখ্যা ≥ ২) ব্যাকএন্ডে ঠিকঠাক
বসানো ও যাচাই করা দরকার, তারপরই তার উপর UI বানানো অর্থবহ; (খ) এই ফিচার
৩টা আলাদা জায়গা ছোঁবে (Dashboard.tsx, Reports.tsx, CallListView.tsx +
exportReports.ts) — একসাথে সব বদলালে ভুল ধরা কঠিন হবে; (গ) থ্রেশহোল্ডের
হিসাব (ধারা ৩) আসল ডেটায় পরীক্ষা করে দেখার জন্য শেষে আলাদা ধাপ দরকার।
প্রতি ধাপের পর `npm run check` + আপনার প্যাকেজড CMD দিয়ে যাচাই হবে, ধাপ
পাস না করলে পরের ধাপে যাব না।

### Phase 1 — ব্যাকএন্ড: "কত মাস বকেয়া" হিসাব + API

- `server/src/routes/dashboard.js`-এ স্ট্যাট কোয়েরিতে যোগ:
  ```sql
  COUNT(*) FILTER (
    WHERE status = 'সক্রিয়' AND fee > 0
    AND FLOOR(due::numeric / fee) >= 2
  )::int AS "riskCount",
  COALESCE(SUM(due) FILTER (
    WHERE status = 'সক্রিয়' AND fee > 0
    AND FLOOR(due::numeric / fee) >= 2
  ), 0)::int AS "riskTotalDue"
  ```
  রেসপন্সের `stats`-এ `riskCount`, `riskTotalDue` যোগ হবে (বিদ্যমান
  `totalDue`/`dueCount` এর পাশে, সেগুলো অপরিবর্তিত থাকবে)।
- `server/src/routes/students.js`-এর `GET /api/students`-এ (যেখানে
  `dueOnly` আছে, ঠিক তার প্যাটার্নে) নতুন `riskOnly` ফিল্টার যোগ:
  ```js
  const riskOnly = req.query.riskOnly === "1" || req.query.riskOnly === "true";
  if (riskOnly) {
    conditions.push(`fee > 0 AND FLOOR(due::numeric / fee) >= 2`);
  }
  ```
  এবং লিস্ট-কলামে একটা কম্পিউটেড `monthsUnpaid` (`FLOOR(due::numeric /
  NULLIF(fee,0))::int`) যোগ হবে, যাতে ফ্রন্টএন্ডে সরাসরি দেখানো যায় (রি-হিসাব
  করা লাগবে না)। `dueOnly` ফিল্টারের প্যাটার্নই কপি হবে, নতুন কিছু
  ভাঙবে না।
- **টেস্ট:** `npm run check` (server syntax check) + ম্যানুয়ালি ২-১টা টেস্ট
  ছাত্রের `due`/`fee` বদলে দেখে হিসাব সঠিক হচ্ছে কিনা যাচাই।

### Phase 2 — ফ্রন্টএন্ড: ড্যাশবোর্ড কার্ড + রিস্ক-জোন লিস্ট ভিউ

- `client/src/modules/Dashboard.tsx`: নতুন `StatCard` — "রিস্ক জোন" (লাল/rose
  রঙ, `riskCount` জন, নিচে `riskTotalDue` টাকা) — বিদ্যমান "বকেয়া ছাত্র"
  কার্ডের ঠিক পাশে। ক্লিক করলে `/reports/call-list/risk`-এ নিয়ে যাবে
  (নতুন `onClick`/লিংক — এখনকার স্ট্যাট কার্ডগুলো ক্লিকেবল না, এই কার্ডটাই
  প্রথম ক্লিকেবল স্ট্যাট কার্ড হবে বলে `StatCard` কম্পোনেন্টে একটা optional
  `onClick` prop যোগ করা লাগতে পারে — বিদ্যমান ব্যবহারগুলো prop না দিলে
  আগের মতোই আচরণ করবে, ভাঙবে না)।
- `client/src/lib/exportReports.ts`, `client/src/modules/Reports.tsx`,
  `client/src/modules/reports/CallListView.tsx` — এই তিন জায়গার
  `ReportKind` ইউনিয়ন টাইপে `"risk"` যোগ:
  - `Reports.tsx`: নতুন রিপোর্ট কার্ড "রিস্ক জোন" (রঙ rose, আইকন
    `alertTriangle`), `CALL_LIST_KINDS`-এ `"risk"` যোগ (যাতে এটাও কার্ড-ক্লিকে
    সরাসরি এক্সপোর্ট না করে কল-লিস্ট পেজে যায়), `REPORT_PERMISSION`-এ
    `students` পারমিশনের সাথে বাঁধা (due/students এর মতোই)।
  - `CallListView.tsx`: `TITLES`-এ `"risk": "কল লিস্ট — রিস্ক জোন (২+ মাস বকেয়া)"`,
    `load()`-এ `kind === "risk"` হলে `api.getStudents()`-এর বদলে নতুন
    `riskOnly=1` প্যারামিটার দিয়ে কল (Phase 1-এর এন্ডপয়েন্ট), টেবিলের
    "বকেয়া" কলামের পাশে/বদলে একটা "কত মাস বকেয়া" কলাম (`monthsUnpaid`)
    দেখানো — কল-বাটন ও কল-মার্কিং লজিক অপরিবর্তিত (already generic, kind
    নির্বিশেষে কাজ করে)।
  - `exportReports.ts`: `REPORT_TITLES`/`RANGE_FILTERED`-এ `"risk"` এন্ট্রি
    (due-এর মতোই date-range-filtered না), CSV/প্রিন্টের কলাম লিস্টে
    `monthsUnpaid` যোগ।
- `client/src/i18n/bn.ts`/`en.ts`: dashboard namespace-এ "রিস্ক জোন" এর
  লেবেল (bn/en দুই ফাইলেই, key-parity বজায় রেখে)।
- **টেস্ট:** `npm run check` (lint+typecheck+build) + ম্যানুয়াল স্মোক-টেস্ট:
  ড্যাশবোর্ড কার্ড দেখা যাচ্ছে, ক্লিকে সঠিক লিস্ট খুলছে, প্রিন্ট/CSV-এ
  মাস-সংখ্যা কলাম আসছে।

### Phase 3 — যাচাই, পলিশ, এজ-কেস, ডক আপডেট

- **আসল ডেটায় থ্রেশহোল্ড যাচাই** (এটা এই ফিচারের সবচেয়ে গুরুত্বপূর্ণ ধাপ,
  কারণ ধারা ৩-এর approximation): আপনার প্রকৃত ছাত্র-ডেটায় কয়েকজন পরিচিত
  "২+ মাস বকেয়া" ছাত্রকে ম্যানুয়ালি চেক করে নিশ্চিত হওয়া যে লিস্টে ঠিক তারাই
  আসছে। গরমিল পেলে থ্রেশহোল্ড/সূত্র এই ধাপেই ঠিক করা হবে।
  Accessibility: নতুন স্ট্যাট কার্ডে `aria-label`/keyboard-focusable (যেহেতু
  এখন এটা ক্লিকেবল)।
- এজ-কেস: `fee = 0` বাদ পড়া ঠিকঠাক কাজ করছে কিনা, ইনঅ্যাক্টিভ ছাত্র বাদ
  পড়ছে কিনা, শূন্য রেজাল্ট (কেউ রিস্ক-জোনে নেই) হলে ভালো একটা ফাঁকা-স্টেট
  মেসেজ।
- `docs/PROJECT_MAP.md`-এ এক লাইন নোট (নতুন `riskOnly` ফিল্টার/স্ট্যাট

## ৫. AGENTS.md / CURRENT_TASK.md সম্পর্কিত নোট

`docs/CURRENT_TASK.md`-এ এখন একটা **অসম্পূর্ণ, ভিন্ন কাজ** পড়ে আছে
(exam-type/result batch-entry — Part 1-3 সম্পন্ন, Part 4 বাকি)। এই
রিস্ক-জোন কাজটা তার সাথে সম্পর্কিত নয়, তাই শুরু করার সময় এটাকে সেই কাজের
Part হিসেবে না লিখে **আলাদা এন্ট্রি** হিসেবে যোগ করা হবে (AGENTS.md-এর
phase-naming rule অনুযায়ী), পুরনো exam-type এন্ট্রিটা যেমন আছে তেমনই থাকবে।
আপনি চাইলে আগে সেই বাকি কাজ (exam-type Part 4) শেষ করাতে পারেন, অথবা এই
নতুন কাজ আগে করতে বলতে পারেন — আলাদা ফাইল/এলাকায় কাজ করছে বলে একসাথেও
এগোনো সম্ভব।

## ৬. পরবর্তী ধাপ

এই পরিকল্পনা ও বিশেষ করে **ধারা ৩-এর অ্যাসাম্পশন** (মাস-সংখ্যা = due ÷ fee,
থ্রেশহোল্ড ≥ ২) পড়ে ঠিক থাকলে **"শুরু কর"** বা **"১ নম্বর থেকে শুরু কর"**
লিখুন — আমি Phase 1 দিয়ে শুরু করব, একবারে এক ধাপ। প্রতিটা ধাপ শেষে আপনার
preference অনুযায়ী শুধু পরিবর্তিত/নতুন ফাইলের zip (E:\ ড্রাইভে সেভ) + একটাই
CMD কমান্ড (এক্সট্র্যাক্ট → npm install (root/client/server) → npm run
check → পাস করলে commit/push, ফেইল করলে থেমে যাবে) দেব।

কোথাও অ্যাসাম্পশন ভুল মনে হলে, শুরু করার আগে বলে দিলে সেভাবে প্ল্যান
এডজাস্ট করে নেব।
