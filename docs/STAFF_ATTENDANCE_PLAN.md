## ১. সমস্যা কী (ব্যবহারকারীর বর্ণনা থেকে)

বর্তমানে `users` টেবিল/`Settings.tsx`-এর "ব্যবহারকারী" সেকশনে যা আছে তা
আসলে **সফটওয়্যার লগইন অ্যাকাউন্ট** (নাম, ইমেইল, পাসওয়ার্ড, রোল — Super
Admin/Admin/Accountant/Teacher/Hostel Manager)। এখানে:

- প্রকৃত স্টাফ/শিক্ষকের তথ্য (ফোন নম্বর, পদবি/designation, যোগদানের তারিখ,
  ছবি, নোট) রাখার কোনো জায়গা নেই।
- যেসব স্টাফ সফটওয়্যার ব্যবহার করবে না (যেমন পিয়ন, দারোয়ান, আয়া) তাদের
  কোনোভাবেই সিস্টেমে রাখার উপায় নেই — কারণ `users` তৈরি করতে বাধ্যতামূলক
  ইমেইল+পাসওয়ার্ড লাগে (`routes/users.js`)।
- স্টাফদের দৈনিক উপস্থিতি (কে আজ স্কুলে এসেছে) রেকর্ড করার কোনো টেবিল/রুট/
  পেজ নেই — `attendance` টেবিল ও `Attendance.tsx` সম্পূর্ণভাবে
  শিক্ষার্থী-কেন্দ্রিক (`studentId` ফরেন-কি)।

## ২. মূল ডিজাইন সিদ্ধান্ত

**`users` (লগইন) আর `staff` (কর্মী তালিকা) — দুটো আলাদা টেবিল, ঐচ্ছিকভাবে
লিংকড।** কারণ প্রতিটা স্টাফের সফটওয়্যার লগইন লাগবে না। নতুন `staff`
টেবিলে একটা nullable `userId` কলাম থাকবে — যে স্টাফের লগইন আছে তার জন্য
Settings-এর বিদ্যমান ব্যবহারকারী তালিকা থেকে একজনকে বেছে লিংক করা যাবে।
লগইন তৈরি/এডিটের UI এখানে ডুপ্লিকেট করা হবে না — সেটা Settings-এই থাকবে,
single source of truth অনুযায়ী।

`staff_attendance` টেবিল হবে হুবহু বিদ্যমান `attendance` টেবিলের প্যাটার্নে
(`studentId` এর জায়গায় `staffId`), যাতে `routes/attendance.js`-এর বাল্ক
upsert লজিক প্রায় হুবহু পুনর্ব্যবহার করা যায়।

## ৪. নতুন যা তৈরি হবে (ফাইল-বাই-ফাইল)

### Phase 1 — DB স্কিমা (protected path, `server/sql/supabase_schema.sql`)

```sql
create table if not exists staff (
  id integer generated by default as identity primary key,
  name text not null,
  phone text default '',
  designation text not null,       -- শিক্ষক/হিসাবরক্ষক/পিয়ন/দারোয়ান/আয়া/অন্যান্য
  class text default '',            -- শুধু শিক্ষকদের জন্য, ঐচ্ছিক (classOptions থেকে)
  "joiningDate" text default '',
  photo text default '',
  status text not null default 'Active',
  "userId" integer references users(id) on delete set null,
  note text default '',
  "createdAt" text not null
);

create table if not exists staff_attendance (
  id integer generated by default as identity primary key,
  "staffId" integer not null references staff(id) on delete cascade,
  date text not null,
  status text not null,
  unique ("staffId", date)
);

create unique index if not exists staff_attendance_staff_date_unique
on staff_attendance ("staffId", date);
```

মাল্টি-টেন্যান্ট মোডে আগে থেকে প্রোভিশন করা যেকোনো টেন্যান্টের জন্য এই দুটো
`create table if not exists` Super-Admin-এর "run SQL on all tenants" টুল
দিয়ে ম্যানুয়ালি একবার চালাতে হবে (ঠিক যেমনটা `own_sms_gateway` ইত্যাদি
নতুন টেবিলের বেলায় করা হয়েছিল) — single-tenant মোডে পরের সার্ভার রিস্টার্টে
এমনিতেই হয়ে যাবে।

### Phase 2 — Backend: Staff CRUD

- `server/src/lib/staffSchemas.js` (নতুন) — `staffCreateSchema`,
  `staffUpdateSchema` (Zod)।
- `server/src/routes/staff.js` (নতুন):
  - `router.use(requirePermission("staff"))`
  - `GET /` — তালিকা (status/designation/search ফিল্টার)
  - `GET /:id` — বিস্তারিত
  - `POST /` — তৈরি, `recordAudit("staff.created")`
  - `PATCH /:id` — এডিট + status টগল, `recordAudit("staff.updated")`
  - হার্ড `DELETE` রুট **থাকবে না প্রথমে** — §৬ দেখুন।
- `server/src/index.js`-এ `app.use("/api/staff", ...)` মাউন্ট (বিদ্যমান
  authenticated চেইনের ভেতরেই)।

### Phase 3 — Backend: Staff Attendance

- `server/src/routes/staffAttendance.js` (নতুন), `routes/attendance.js`-এর

### Phase 4 — RBAC (protected path, `server/src/config/roles.js`)

দুটো নতুন পারমিশন-কী যোগ হবে: `"staff"` এবং `"staffAttendance"`।

ডিফল্ট গ্রান্ট (প্রস্তাবিত, §৬-এ কনফার্ম করুন):
- Super Admin: এমনিতেই `"*"` দিয়ে সব পায়।
- Admin: `"staff"` + `"staffAttendance"` দুটোই যোগ হবে।
- Accountant/Teacher/Hostel Manager: কিছুই যোগ হবে না ডিফল্টে (§৬-এর প্রশ্ন
  ১ দেখুন — Hostel Manager-কে `staffAttendance` দেওয়া হবে কিনা)।

`ROUTE_PERMISSION`-এ যোগ হবে:
```js
"/api/staff": "staff",
"/api/staff-attendance": "staffAttendance",
```

`npm run check` স্বয়ংক্রিয়ভাবে `client/src/lib/roles.generated.ts`
রিজেনারেট করবে — এটা হাতে এডিট করা হবে না (AGENTS.md rule 3)।
